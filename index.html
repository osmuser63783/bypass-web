Wizard

Describe what to find; it becomes an Overpass query you can edit. This is Overpass Turbo's wizard, with iD's preset names.

    
Syntax
      

        
Drinking Water
a feature name from iD (synonyms work too: "water fountain")

        
amenity=cafe
a tag

        
shop=*
has the key, any value

        
opening_hours!=*
doesn't have the key

        
name~castle
value matches a regular expression; name~/castle/i ignores case

        
… and … / … or …
combine conditions; brackets work

        
type:node
only points (or way, relation)

        
… around Leith
within 1 km of a place, looked up by name in the saved area

        
… in Leith
inside a named area, looked up by name in the saved area

        
… global
the whole saved area instead of the map view

        
cafe without a wheelchair tag
the tag is missing: not mapped yet, which isn't wheelchair=no (with: has the tag, any value)

        
pub named crown
name contains the word, any case

        
bench within 200 m of Leith
around a place, with your own radius (m or km)

        
cafes within 200 m of a pub
near any feature of a kind (near: within 100 m); plurals and "a"/"the" are fine

        
shop not checked for 2 years
check_date older than that, or none

About this page

    
Questions and problems

    
Please report problems and ask questions on the issue tracker.

    
How accurate are the results?

    
Bypass reads the same query language as Overpass, and its answers have been checked against the real Overpass API running on the same map data. The test covers about 3,000 queries, real and synthetic ones. The answers match (the same objects, with the same tags and shapes, in the same order), except the following known differences:

    
    
      
  • The data is up to a day old: public Overpass servers are usually minutes behind OpenStreetMap. The data Bypass uses is rebuilt once a day (its date is in the header), so to check today's edits, come back tomorrow and click Load this area: when newer data is out, it offers to update your saved area before you rerun your query.
    • 
      
  • Only inside your saved area: the data is complete inside the outlined area. Results beyond it may be missing; they're dimmed, and Load this area fills the gap. A query about a place that reaches outside it asks you to load the rest.
    • 
      
  • Relations that reach beyond your saved area, such as a bus route, a long-distance path or a country's border: Bypass finds the relation, but its members outside the saved area are missing from everything: the member list in the results, its shape on the map, its members (>) and member counts. Overpass always has the whole relation. When a query lists or follows them, the Notes tab says some are missing; loading the rest of the area completes the relation. A relation used as an area (a boundary in area[…] or map_to_area) is never used with part of its outline: the query asks you to load the rest instead.
    • 
      
  • No edit history: with Overpass, you can check who edited what and when, version numbers and old states of the map. Bypass does not support this. Queries that ask for them (out meta, [date:], [diff:], filters on user or version) are refused rather than answered without them. Load into JOSM fetches the current versions from OpenStreetMap when you want to edit.
    • 
      
  • Place names ({{geocodeArea:…}} and the like) are looked up in the saved data using a crude set of rules, not on Nominatim. For a name that several places inside the saved data share, the results may differ. The Notes tab says which place was used.
    • 
      
  • Overpass's own mistakes aren't copied: in a few rare cases Overpass gets an answer wrong. Bypass follows Overpass's documented rules there, so its answer differs and is the right one.
    • 
      
  • Right on a border: a point within about a centimetre of an area's boundary can land on the other side.
    • 
      
  • Very broad queries: a search whose only condition is a calculation (if:) or "not equal to" would have to read everything, which Overpass does slowly. Bypass stops with "Filters too weak": add a tag or an area to narrow it.
    • 
      
  • Error messages for broken queries are the same as Overpass's, apart from a handful worded more plainly.
    • 
    

    
Privacy

    
    
This page has no accounts, cookies, analytics or tracking. Queries run in this tab: their text and results aren't sent anywhere.

    
    
Your browser does contact these servers, and each of them sees your IP address, as any website does:

    
    
      
  • the site serving this page: Cloudflare Pages (Cloudflare's privacy policy);
    • 
      
  • the background map: OpenFreeMap, or openstreetmap.org's tiles if you pick them. It also sees which part of the world you look at. "No basemap" avoids it;
    • 
      
  • the bundle, when you load or update an area: by default download.openplanetdata.com, which logs the file, time, IP address and user agent (Open Planet Data's privacy policy). The parts of the file you fetch show roughly which area you loaded;
    • 
      
  • any address a query's style: section names (styles, tiles, icons). A shared link whose query does this doesn't run until you press Run.
    • 
    

    
Only when you click: Load into JOSM talks to JOSM on your own computer, which then downloads the objects from the OpenStreetMap API. Open in CoMaps puts the results' names and positions in the link, so comaps.at sees them if the app isn't installed. Links to openstreetmap.org, Wikidata and other sites open those sites.

    
Kept in this browser, for this site only: saved areas, saved queries and settings. Saved areas has Delete; clearing this site's data in your browser removes everything.

    
Share links carry the query and map view after the # in the address: anyone who opens the link can read them, but browsers don't send that part to the site serving this page.
